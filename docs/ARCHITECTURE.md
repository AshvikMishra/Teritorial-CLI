# Territorial CLI: Architecture and Cross-Crate Contracts

This document is the source of truth for how the crates fit together. It refines
`PRD Territorial CLI.md` and records the decisions made for the open questions.
If code and this document disagree, fix one of them; don't let them drift.

## 0. Decisions on the PRD open questions

| # | Question | Decision |
| --- | --- | --- |
| 1 | Region values | **Hybrid.** mapgen derives a value from area and population (square-root compressed, clamped 1..=30). Hand overrides live in `mapgen/curation.json`. |
| 2 | Default attack percent | **Per target type.** Settings have `default_attack_pct_neutral` (default 25) and `default_attack_pct_enemy` (default 40). |
| 3 | Alliances | **In v1.** `ally <player>` proposes or accepts, `unally <player>` breaks. Allies cannot attack each other. Bots propose, accept and break alliances. |
| 4 | Minimum terminal size | **Auto compact mode** below 100x30. Refuse to draw the game (show a "terminal too small" notice) only below 60x20. |
| 5 | Replays | **In v1.** A replay file holds config, balance, seed and the human command log. `territorial --replay <file>` plays it back. Bots regenerate their commands deterministically. |

Other decisions:

- **mapgen is a Python 3 (stdlib only) tool**, not a Rust crate. It is a build-time
  tool that is never shipped. Its output is committed to `assets/`, so normal
  builds need neither Python nor network access.
- Pinned UI stack: `ratatui = "0.29"`, using **its re-export of crossterm**
  (`ratatui::crossterm`, which is crossterm 0.28). No direct crossterm dependency,
  so versions cannot mismatch.
- No `rand` crate. Core ships its own SplitMix64/xorshift RNG so determinism
  doesn't depend on an external crate's algorithm.
- Human player is always `PlayerId 0`. Bots are `1..=n`.

## 1. Workspace layout

```
Cargo.toml            workspace (members: core, render, ui, cli)
assets/
  world_regions.json  generated by mapgen: regions, edges, raster meta
  world_bitmap.bin    generated by mapgen: RLE region-id raster
  balance.toml        every tunable gameplay number (embedded; overridable with --balance)

render/  territorial-render (lib territorial_render) map rasterizer, camera, themes, capability detection, ASCII art
ui/      territorial-ui     (lib territorial_ui)     ratatui app: screens, layout, command line, parser, input
cli/     territorial        (bin territorial)        clap flags, settings + save/replay file I/O, headless sim
mapgen/  mapgen.py + curation.json                    Natural Earth -> assets/
docs/    ARCHITECTURE.md (this file)
```

Dependency direction: `cli -> ui -> render -> core`, and `cli -> core/render`.
`core` depends only on `serde` and `serde_json`.

## 2. Map asset format (mapgen output, core input)

### 2.1 `assets/world_regions.json`

```json
{
  "version": 1,
  "raster": { "width": 1440, "height": 560, "cells_per_degree": 4, "lat_top": 84, "lon_left": -180 },
  "regions": [
    {
      "id": 0,
      "code": "ad",
      "name": "Andorra",
      "continent": "Europe",
      "value": 1,
      "area_km2": 468,
      "population": 77000,
      "label": [722, 105],
      "cells": 1
    }
  ],
  "edges": [
    { "a": 0, "b": 57, "kind": "land", "length_km": 512 }
  ]
}
```

- `id`s are contiguous `0..regions.len()` and regions are sorted by `code`.
- `code` is unique, lowercase ASCII `[a-z0-9-]`. Countries use ISO 3166-1 alpha-2
  (`fr`, `br`). When that is missing, they use a lowercased 3-letter code. Split
  sub-regions use `<iso2>-<suffix>`, for example `us-w`, `ru-e`, `ca-qc`.
- `continent` is one of: `Africa`, `Asia`, `Europe`, `North America`, `South America`, `Oceania`.
- `value` is an integer from 1 to 30.
- `label` is `[x, y]` raster coordinates of a cell inside the region, near its visual center.
- `edges` are undirected, `a < b`, and contain no duplicates. `kind` is `"land"` or `"sea"`.
  `length_km` is the great-circle distance between the two labels, at least 50.
- Raster cell `(x, y)` covers lon `[lon_left + x/cpd, lon_left + (x+1)/cpd)` and
  lat `(lat_top - (y+1)/cpd, lat_top - y/cpd]`. Row 0 is the north edge.

### 2.2 `assets/world_bitmap.bin` (little-endian)

```
magic   4 bytes  "TBMP"
version u16      1
width   u16
height  u16
then for each row y in 0..height:
  run_count u16
  run_count x { region u16 (0xFFFF = ocean / no region), length u16 }
  (the lengths in a row sum to width)
```

### 2.3 Validation (mapgen enforces; core re-checks cheaply on load)

- The graph (land plus sea edges) is connected.
- There are 150 to 220 regions.
- Every region has at least 1 raster cell.
- No region holds more than 4% of total world value.

### 3.2 Balance (`balance`)

`Balance` is a flat `#[derive(Clone, Debug, Serialize, Deserialize)] #[serde(default)]`
struct of **integer** fields. Percent and permille fields are named `*_pct` and
`*_permille`. `Balance::default()` must equal the values in `assets/balance.toml`
exactly, and every field must appear in that file with a comment. The cli parses
TOML and core never touches TOML.

### 3.6 Simulation rules (all integer math, deterministic)

- **Tick order** in `step()`:
  1. `tick += 1`.
  2. Apply queued commands in queue order, re-validating each. Rejections become `CommandRejected`. Human commands go into `command_log` with this tick.
  3. Run bots whose reaction timer is due, in ascending player id. Their commands are applied immediately through the same validation code.
  4. Economy: pool growth, then garrison regen.
  5. Advance marches. Resolve arrivals ordered by `(arrive_tick, march id)`.
  6. Recalls arrive.
  7. Expire proposals and truces.
  8. Eliminations, then win check.
- **Pool growth** is logistic: `growth = (base + per_value * owned_value + pool * rate) * (cap - pool) / cap`, scaled by `growth_scale_pct`, accumulated in milli-troops so fractions aren't lost. `cap = cap_base + cap_per_value * owned_value`.
- **Garrison regen** moves each owned region toward `regional_cap = garrison_cap_base + garrison_cap_per_value * value`, slowly. Neutral regions start at `neutral_garrison_base + neutral_garrison_per_value * value` and don't regenerate above it.
- **Attack**: the target must be adjacent (land or sea edge) to a region the attacker owns. The march departs from the owned neighbor with the shortest edge (ties go to lower id). `eta_ticks = max(min_march_ticks, length_km * march_ticks_per_1000km / 1000)`. Troops leave the pool immediately. A Percent amount is a percent of the current pool, and the attack is rejected if it resolves to less than 1.
- **Arrival**: if the target is now owned by the attacker, troops join the garrison (`Reinforced`). If it is owned by an ally (allied after departure), troops return to the pool. Otherwise: `def = garrison * bonus_permille / 1000`. If `troops > def`, the attacker captures it, `garrison = troops - def`, and the region gets `fortified_until = 0`. Otherwise both sides lose: the defender loses `troops * 1000 / bonus_permille` garrison (minimum 0) and the attackers are destroyed (`AttackRepelled`). Several arrivals stack naturally because each one is processed against the updated garrison.
- **Defender bonus** permille = `defense_base_permille`, plus `capital_bonus_permille` if the region is its owner's capital, plus `fortified_bonus_permille` while `tick < fortified_until`. Neutral regions use `neutral_defense_permille`.
- **Fortify** moves pool to garrison and sets `fortified_until = tick + fortify_duration_ticks`.
- **Recall** removes troops from the garrison immediately (the garrison keeps at least 1) and returns them to the pool after `recall_delay_ticks`.
- **Elimination** happens when a player owns zero regions. Their marches and recalls vanish, and their alliances end.
- **Capital**: the start region. If it is lost while the player is still alive, the capital moves to their highest-value region.
- **Start regions**: random starts are spaced so that start regions are at least `start_min_hops` graph hops apart (relaxed if impossible). Starting garrison and pool come from balance.
- **Alliances** (only when `config.alliances`): `ProposeAlliance{with}` forms the alliance if `with` already proposed to the proposer. Otherwise it records a proposal that expires after `proposal_ttl_ticks`. A player can have at most `max_allies` allies. `BreakAlliance` ends it immediately and starts a truce of `truce_ticks` during which neither side may attack the other. Allies can't attack each other, and marches already in flight toward a new ally return to the pool on arrival.
- **Win checks**, in order:
  1. **Domination**: `land_pct >= pct`. One winner, chosen by highest score if several qualify.
  2. **Elimination**: one player alive, or, in Elimination mode only, every alive player is in one mutual alliance clique. That gives `AlliedVictory`, and `top` is the highest score.
  3. **Timer**: at the time limit, in Timed matches, the highest score wins. Ties go to the lower id.
  4. With `Timed`, only rule 3 applies.

  The human being eliminated does not stop the sim. The UI shows the defeat screen and may let bots finish.

### 3.7 Smart targets (`targets`)

```rust
pub enum SmartTarget { Weakest, Richest, Player(PlayerId) }
pub fn resolve(game: &Game, p: PlayerId, t: &SmartTarget) -> Result<RegionId, CommandError>;
```

- `Weakest`: the attackable region with the lowest `effective_defense`, preferring regions owned by enemy players. It falls back to neutral regions when no enemy region borders you. Ties go to higher value, then lower id.
- `Richest`: the attackable region with the highest value. Ties go to lower defense, then lower id.
- `Player(x)`: the attackable region owned by `x` with the shortest edge to your territory. Ties go to lower defense, then lower id. It returns an error if there's no border.

### 3.8 Bots (`bots`)

- Each bot has a `Personality { Aggressor, Turtle, Opportunist, Warlord }` and a `Difficulty`.
  `Mixed` difficulty is assigned round-robin or by RNG at `Game::new`.
- Reaction interval in ticks: Easy 60..=100, Normal 30..=50, Hard 10..=20, re-rolled from the game RNG after each decision.
- Each decision enumerates legal commands (attacks on each attackable region at a few amount levels, fortify on threatened borders, recall from safe interior regions, alliance actions), scores them with integer utility (gain, risk, distance, personality weights, difficulty-dependent noise and odds evaluation), and issues **at most one** command through the same validation path as the human. The bot issues nothing if no command has positive utility.
- Easy bots ignore defense and send fixed fractions. Normal bots check odds (`troops > defense * margin`). Hard bots also time attacks to land together, exploit regions emptied by wars, and fortify threatened borders.
- The anti-stall rule: after `stall_ticks` with no capture anywhere, bots raise their aggression so the match always ends.

Rendering rules:

- Half-block `▀` mode: fg is the top pixel and bg is the bottom pixel.
- ASCII mode: one pixel per cell, using `#`, `+` and `.` for owned, border and neutral, with 16 colors.
- Borders are drawn as a shade shift where the right or below neighbor pixel is a different region.
- Labels (`code` plus garrison) are drawn at region labels at Continent zoom or closer, and at World zoom for large regions if they fit.
- Marches are drawn as an arrow glyph interpolated between source and target labels (`→←↑↓↗↘↙↖` in Unicode mode, `> < ^ v` in ASCII mode).
- The highlight region pulses with `anim_frame`.
- With `crosshair`, a `✛` (ASCII: reversed `+`) in the highlight color is drawn on the
  cell where `(cx, cy)` actually lands. That is the view center except when the
  whole map height fits and the renderer centers the map vertically.
- Zoom scales are raster cells per screen pixel: World = fit the whole width, Continent = 2.0, Region = 0.75 (about 1 raster cell per pixel or finer).

   fn save_replay(&mut self, replay: &Replay) -> Result<String, String>; fn save_settings(&mut self, s: &Settings) -> Result<(), String>; }`
- `Settings` (serde, `#[serde(default)]`): `theme: ThemeKind`, `renderer: RendererChoice`,
  `default_attack_pct_neutral: u8`, `default_attack_pct_enemy: u8`, `aliases: BTreeMap<String, String>`,
  `history_size: usize`, `show_hints: bool`, `last_config: Option<MatchConfig>`.
- Screens: Splash, then Setup, then optional ChooseStart (map with the crosshair: arrows/zoom/Tab move it, Enter starts in the region under it, `:` opens a prompt to type a region, Esc goes back), then Countdown (3, 2, 1, GO), then Playing, then GameOver (victory or defeat plus stats, `enter` for a new match, `q` to quit). Replay mode goes Playing (read-only), then GameOver.
- The input thread reads crossterm events into an `mpsc` channel. The main loop runs the sim at 10 Hz × speed, drains input, and redraws at most 30 to 60 FPS, and only when dirty or animating.
- The command system (module `command`): tokenizer, `;` chaining, `!!`, user aliases with `$1..$9`/`$*`, verb aliases, fuzzy region resolution (exact code, then exact name, then prefix, then subsequence, then edit distance <= 2), smart targets, ghost-text completion (Tab accepts), a live hint strip from `Game::preview`, history (Up and Down), and Esc to clear.
  UI-only verbs: `info|i`, `focus|w`, `status|s`, `speed|sp`, `pause|p`, `alias`, `unalias`, `help|h`, `save|sv`, `quit|q`, `theme`.
  Game verbs: `attack|a`, `fortify|f`, `recall|r`, `ally|al`, `unally|ua`.
- Input on the Playing screen has two modes. The bottom row always shows which:
  a dim key cheat strip in hotkey mode, the `> ` prompt in prompt mode.
- **Hotkey mode** (the default). The selection is the region under the camera
  center (the crosshair): `Raster::region_at(cx, cy)`, or over the ocean the
  region whose label is nearest within 6 screen pixels (at least 6 raster
  cells). It pulses like any highlight, and the hint strip previews it (name,
  code, owner, garrison, value, and what `a` would do via `Game::preview`).
  Keys act at once, without confirmation:
  - Arrows pan (Shift or Ctrl: 4x). `+`/`=` zoom in, `-`/`_` zoom out.
  - Tab / Shift+Tab snap the center to the next / previous attackable region
    (`Game::attackable_regions`, ordered by label distance from your capital,
    ties by id). `o` / `O` snap through your regions (value desc, then id),
    `c` to your capital. Cycles remember their position. A snap keeps the zoom.
  - In hotkey mode the UI sets `Camera::free_y`, so the center can go past the
    band the view can center on: at the top and bottom of the map the view
    stops and the crosshair moves off center, and every row stays reachable.
  - `a` attack, `f` fortify, `r` recall the selection with `Amount::Percent(send)`.
    `w` / `e` attack `@weakest` / `@richest` (`targets::resolve`) and snap there.
    `1`..`9` set the sticky amount to 10%..90%, `0` to 100%; it starts at
    `default_attack_pct_enemy` rounded to 10 and shows in the status bar.
  - `l` / `u` ally / unally the selection's owner; `y` accepts the newest
    proposal made to you.
  - `i` info panel, `s` status, `p` or Space pause, `[` / `]` step the speed
    (0.25x, 0.5x, 1x, 2x, 4x, 8x), `t` cycles the theme (persisted), `?` or `h`
    help, `.` repeats the last hotkey command (same target) or the last
    submitted line, PageUp/PageDown scroll the log (or help), Esc closes help
    and panels or clears the error. Unknown keys do nothing.
  - Hotkey game commands use the typed path: `parser::describe_command` validates
    with `Game::preview` and builds the same hint; a rejection shows its reason
    and queues nothing; success calls `Game::queue(HUMAN, cmd)` and flashes the
    hint in the event log.
  - Read-only sessions (replay, spectating) refuse `a f r w e l u y` with the
    read-only error; everything else works.
- **Prompt mode** (`:` or Enter). The typed command line, unchanged:
  - Enter submits; success returns to hotkey mode, a rejected line stays with its reason.
  - Esc clears a non-empty line, and on an empty line returns to hotkey mode.
  - Tab accepts ghost text. Up and Down browse history. Left, Right, Home, End,
    Backspace and Delete edit the line.
  - Shift or Ctrl plus arrows pan. `+` and `-` zoom only when the line is empty,
    because region codes contain `-`.
  - PageUp and PageDown scroll the event log.

## 6. CLI crate (`territorial`)

- Flags: `--preset`, `--minutes`, `--bots`, `--difficulty`, `--win`, `--domination-pct`, `--seed`,
  `--start <region>`, `--no-alliances`, `--theme`, `--renderer`, `--balance <file>`, `--load <save>`,
  `--replay <file>`, `--quick` (skip splash and setup), `--simulate` (headless bot-only match, prints the result),
  `--max-ticks <n>` (simulate guard).
- Paths, with no `dirs` crate:
  - Config: `$XDG_CONFIG_HOME` or `~/.config` + `/territorial/settings.json`. On Windows, `%APPDATA%\territorial\settings.json`.
  - Data: `$XDG_DATA_HOME` or `~/.local/share` + `/territorial/{saves,replays}`. On Windows, `%APPDATA%\territorial\...`.
- Saves and replays are JSON (`serde_json`).
- The balance file is TOML: the embedded `assets/balance.toml`, overridden by `--balance`.
